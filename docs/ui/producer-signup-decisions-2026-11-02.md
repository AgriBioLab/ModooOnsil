# 생산자 회원가입 — 2차 스프린트 기술기준·후속 운영정책

작성일: 2026-11-02
범위: 공공기관 제공 영농 지원 서비스의 2차 스프린트 기술 합의와 후속 운영 검토. 실제 계정 생성 API나 인증 기능을 구현한 문서는 아니다.

## 0. 2차 스프린트 기술 합의 우선

사용자 추가 지침: **공공기관이 제공하는 영농 지원 서비스**를 전제로 한다. 이번 2차 스프린트는 회원가입·로그인·본인 영농정보 접근의 기술 기준과 검증을 우선한다. 최종 약관 문구·법무 검토·상세 운영정책은 후순위로 분리하고 기술 검증의 선행 완료 조건으로 두지 않는다.

기존 프로젝트의 Spring 계층·데이터 접근·DB·비밀번호 해시 계약과 연계한다. 아래는 팀 기술 합의·구현 검토안이며 이미 구현하거나 팀 합의를 완료한 항목으로 표시하지 않는다.

서비스 참고는 농업e지·농업ON이며, 계약 고객만 초대하는 상용 서비스 모델을 기본 전제로 두지 않는다. 이번 합의한 가입 대상(농장 대표·관리자 우선)과 아이디·비밀번호 방식은 유지한다. 공공 본인인증·농업경영체 조회의 실제 연계 또는 모의/미연결 범위는 T06에서 구분한다.

## 1. 이번 대화에서 합의한 사항

| 항목 | 합의한 내용 | 반영 |
| --- | --- | --- |
| 가입 대상 | 농장 대표·관리자 우선 | 생산자 전용 가입 화면. 직원·담당자 통합 가입으로 확대하지 않음 |
| 로그인 방식 | 아이디·비밀번호 | 아이디·비밀번호·확인 입력 |
| 기존 사용자 구분 | 기존 품질담당자 로그인 유지 | 생산자 가입 진입을 별도로 추가 |
| 프로토타입 범위 | 가입 흐름을 확인하는 화면 | 실제 가입·문자 발송·본인확인·중복 조회·권한 부여 없음 |

농장 대표/관리자라는 가입 대상과 실제 농장 접근 권한은 다르다. 가입만으로 기존 농장의 관리 권한을 자동 부여하지 않는다. 실제 권한 확인 방식은 별도 합의사항이다.

## 2. 화면 흐름과 입력안

약관·개인정보 확인 → 회원정보 입력 → 완료 화면 → 영농 화면 미리보기.

- 첫 화면에서 서비스 이용약관과 개인정보 수집·이용을 구분해 확인한다.
- 동의 항목은 미선택 상태로 시작하며 각 항목의 내용을 열고 닫을 수 있다. 일괄 동의와 개별 동의를 연결한다. 미동의 상태로 다음 단계를 누르면 해당 항목에 오류를 표시한다.
- 동의하지 않고 나가는 경로도 제공한다.
- 회원정보 입력: 이름·아이디·비밀번호·비밀번호 확인·휴대전화번호. 최소 입력안이며 이름/휴대전화 필수 여부는 목적과 실제 복구 방식에 맞춰 최종 확정한다.
- 회원가입과 농장 등록을 분리한다. 농장명·주소·온실·품종·재배 수량·영농 기록은 가입 완료 후 등록한다.
- 시안의 아이디 규칙은 영문 소문자 시작, 6~20자 영문 소문자·숫자다. 비밀번호 10~64자는 UI 확인용 임시 규칙이며 최종 보안 정책을 확정한 것으로 보지 않는다.
- 휴대전화번호는 형식만 확인한다. 번호 입력을 본인인증 완료나 소유권 확인으로 표시하지 않는다.
- 완료 화면은 실제 계정이 생성되지 않았음을 표시하고, 입력 필드를 비운다. 이름·아이디·전화·비밀번호·동의 선택을 localStorage/sessionStorage나 서버에 저장하지 않는다.
- 실제 로그인이나 가입 성공으로 처리하지 않고 '영농 화면 미리보기'로 이동한다.

## 3. 가입자에게 제시할 동의·고지

이 절의 최종 문구·법무·처리방침 검토는 후속 과제다. 현재 UI 초안은 유지하며, 이 절 전체의 확정을 이번 기술 스프린트의 선행 완료 조건으로 두지 않는다.

| 항목 | 시안 처리 | 실서비스 적용 전 합의 |
| --- | --- | --- |
| 서비스 이용약관 | 필수 동의 제안, 내용 초안 제공 | 운영 주체·서비스 범위·계정/농장 권한·탈퇴·기록 반환/보관·이용 제한·이의제기·변경 고지 |
| 개인정보 수집·이용 | 별도 필수 동의 제안, 목적·항목·기간·거부 관련 항목을 나누어 표시 | 처리 근거, 필수 수집 필요성, 개인정보처리자·문의처, 보유기간과 실제 거부 시 영향 |
| 선택 정보·홍보 수신 | 현재 가입 필수 항목에 포함하지 않음 | 실제 필요할 때 목적·항목·선택 여부·철회 방법을 정하고 별도 제공 |
| 외부 기관 제출·제3자 제공 | 가입 시 포괄 동의로 처리하지 않음 | 제공받는 자·목적·항목·기간·거부 관련 사항 등 실제 기능에 맞춰 검토 |
| 개인정보 처리방침 | 최종 문서 확정 필요 | 처리방침 공개와 개별 처리 동의를 혼동하지 않고 실제 처리 내용에 맞게 제공 |

동의가 필요한 처리와 다른 법적 근거로 처리하는 경우를 먼저 구분한다. 모든 개인정보 처리가 언제나 필수 동의 대상이라고 단정하지 않는다. 개인정보 수집·이용 동의를 근거로 삼을 때에는 목적·항목·보유기간·거부 관련 고지를 확인한다. 선택 정보 거부를 이유로 기본 서비스를 제한하지 않는 구성을 검토한다. [개인정보 보호법 제15·16조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?lsJoLnkSeq=1029334879)

현재 화면의 '운영정책 확정 필요'는 누락을 숨기지 않기 위한 시안 표기다. 운영기관·보유기간이 비어 있는 현재 문구를 실제 가입 동의서로 사용하지 않는다. 운영기관이 정해지면 항목별 처리 근거·필요성을 확인하여 문구와 화면을 확정한다.

## 5. 개발 연결 목록 — 적용 시점은 0절 기술 범위에 따름

- 계정 생성·중복 확인·비밀번호 검증/보관·로그인·계정 복구 서버.
- 필요한 인증 수단과 실패·재시도·만료 처리.
- 농장 생성·초대·위임·역할 권한과 승인 이력.
- 최종 약관/동의 문서 버전·선택 여부·실제 동의 시각·철회 이력.
- 회원 탈퇴와 농장 공동 기록의 보관·이관·반환/삭제 흐름.
- 회원가입 API 성공 전 완료로 처리하지 않고, 이미 가입됨·오류·승인 대기를 별도 처리.

실제 개인정보·비밀번호를 브라우저 저장소나 로그에 남기는 방식으로 연결하지 않는다. 이번 프로토타입은 프런트 화면만 검토한다.
