# 손그림 프로토타입 기반 생산자 메인 리서치

작성일: 2026-10-31  
범위: 사용자 스케치 해석, 공식 서비스·기술자료 조사, 데이터 항목 대조, 정보구조·검증 계획. 화면 코드는 이번 조사에서 변경하지 않음.

## 1. 설계 방향부터 정정

스케치의 중심은 **작업 전 농장 상태를 확인하고, 작업 후 기록을 남기는 생산자의 일상 업무**다. 서비스 소개보다 사용 중인 농장의 오늘을 보여주는 화면이 필요하다.

앞선 시안은 목록 화면을 메인에 배치했다가, 다시 서비스 소개형 홈으로 바꾸는 과정에서 실제 사용 맥락을 충분히 검증하지 못했다. 이번에는 아래 질문을 중심으로 판단한다.

1. 오늘 어느 온실·베드에서 무슨 작업을 해야 하는가?
2. 선택한 온실에서 무엇을 재배하며, 현재 어떤 상태인가?
3. 날씨·알림 때문에 오늘 계획을 바꿀 필요가 있는가?
4. 작업 결과와 이번 달 입출금 내역을 빠르게 남기고 다시 확인할 수 있는가?

이는 스케치와 기존 프로젝트 페르소나에서 도출한 설계 가설이다. 사용자 인터뷰나 현장 사용성 검증이 끝났다는 의미는 아니다.

## 2. 스케치에서 읽은 구조

아래쪽 스케치를 주 기준으로 삼았다. 필기가 불명확한 부분은 단정하지 않았다.

| 영역 | 관찰한 내용 | 설계에서 확인할 것 |
| --- | --- | --- |
| 상단 | 화훼 로고, 농업인 이름, 로그아웃 | 서비스명·계정·현재 농장 구분 |
| 주요 메뉴 | 재배관리, 장부, 영농일기, 마이영농 | 작업기록과 자유형 일기의 관계, 장부·농장정보의 책임 |
| 왼쪽 위 | 오늘 할 일, 더보기, 작업 체크 | 예정·실시·완료의 차이, 대상 베드, 자동운전 일정 구분 |
| 가운데 | A/B/C 온실 탭, 추가, 장미·품종, 진행률 80%, 시작일·출하예정일 | 온실 안 다품종·다회차, 진행률 의미, 반복 수확 |
| 왼쪽 아래 | 10월 재해정보와 안내 | 지역·작목 관련성, 발생/발표/유효 시각, 공식 출처 |
| 가운데 아래 | 지역이 표시된 여러 날의 날씨 | 농장 위치 기준, 실외예보·실내센서 구분, 예보 범위 |
| 하단 | 월 지출·수입·차액 | 현금 입출금인지 판매·비용인지, 실제값·예상값 구분 |

**유지할 중심 구조:** 오늘 할 일 + 온실별 재배현황을 가장 먼저 보여주고, 날씨와 지역 주의정보, 월 장부 요약을 연결한다.

## 3. 실제 서비스에서 확인한 설계 근거

### 3.1 Priva Operator — 선택한 구역에서 지금 확인할 정보를 모은다

공식 대시보드 소개는 온실 공정 상태와 조치가 필요한 항목을 요약하고, 측정값·설정·상세화면에 빠르게 접근하도록 설명한다. 작물·구역별 대시보드 구성도 제시한다. [Priva 공식 소개](https://www.priva.com/horticulture/connext-operator-dashboard-features)

**이번 설계에 적용:** A/B/C동 선택은 유지하되 현재 선택한 동·베드·품종을 명확하게 표시한다. 상세 환경 그래프는 필요할 때 열도록 하고, 메인은 현재 단계·최근 기록·다음 작업을 요약한다.

**적용 한계:** Priva의 장비 연동·제어 기능을 우리 프로젝트가 이미 갖춘 것으로 가정하지 않는다. 제품 소개는 기능 근거이며 우리 사용자의 효용이 검증됐다는 증거는 아니다.

### 3.2 Agri-note — 작업 예정과 실제 기록을 연결해 입력 부담을 줄인다

공식 도입 사례에는 작업 예정에 약제·작업자·시간을 미리 등록하고 현장에서는 적은 조작으로 실적을 기록하는 흐름이 나온다. 작업·생육·수확·출하 기록을 다음 계획에 참고하는 사례도 제시한다. [공식 사례](https://www.agri-note.jp/cases/case29/)

2026-02-24 공식 업데이트는 선택한 작부와 연결된 포장의 작업·기계·수확 정보를 보고, 현재 표시 조건을 명확하게 보여주는 개선을 설명한다. [2026년 공식 업데이트](https://www.agri-note.jp/2026/02/update_20260224/)

**이번 설계에 적용:** ‘오늘 할 일’을 완료할 때 대상·작업 종류·예정일을 다시 입력하지 않게 한다. 실제 완료시각과 필요한 작업 결과를 확인해 기록으로 연결한다. 온실을 바꾸면 바뀌는 영역과 전체 농장 기준 영역을 구분한다.

**적용 한계:** 해당 도입 사례는 채소 농장이다. 이 흐름을 화훼 농가에 그대로 일반화하지 않고 참고 가설로 사용한다.

## 4. 화면에 영향을 주는 핵심 조사 결과

### 4.1 ‘재배 진행률 80%’는 의미를 먼저 정의해야 한다

농사로의 절화장미 자료에는 한 번 식재해 여러 해 재배하는 특성이 설명되어 있다. 따라서 온실 한 동의 최초 정식일부터 단 한 번의 출하일까지를 재배 전체로 보는 모델은 장미 운영을 충분히 담기 어렵다. [농촌진흥청·국립원예특작과학원 자료, 2016년](https://www.nongsaro.go.kr/portal/ps/psb/psby/vodPlay.ps?menuId=PS65512&mvpNo=1154)

이 자료는 재배 구조를 이해하는 참고로 사용했다. 과거 품종·온도·약제 수치를 현재 농가의 권장 기준으로 채택하지 않았다.

| 의미 후보 | 필요한 근거 | 표시 이름 |
| --- | --- | --- |
| 계획한 기간 중 지난 기간 | 선택한 재배·생산 단위의 시작일과 목표일 | 계획기간 경과율 |
| 계획 작업 중 완료한 비율 | 같은 범위의 확정 작업 목록과 완료 기록 | 예정 작업 완료율 |
| 실제 작물의 성숙 정도 | 품목·품종별 측정·관찰 기준과 검증 | 기준 확보 전에는 수치 표시 보류 |

**제안:** 의미가 확정되기 전에는 ‘현재 단계 / 최근 확인일 / 다음 수확·출하 예정일’을 먼저 표시한다. 경과일은 경과일로, 예정일까지 남은 날은 D-day로 분리한다. 출하예정일이 바뀌었다고 작물의 실제 생육 상태가 바뀐 것처럼 보여서는 안 된다.

장미처럼 반복 수확하는 경우 다음 구조를 검토한다.

`농장 → 온실 → 베드·구역 → 재배 건 → 여러 수확·출하 기록`

현재 단계의 명칭과 단계 전환 조건은 실제 재배자의 관리 방식으로 검증한다. 국화·호접란·장미를 하나의 보편적인 단계·기간으로 묶지 않는다.

### 4.2 날씨는 농장 실외예보와 온실 내부 상태를 구분한다

기상청 API허브는 발표시각과 예보 대상시각을 구분하며 기온·최고/최저기온·바람·하늘상태 등 변수를 제공한다. 안내상 예보 범위도 발표시각에 따라 달라진다. 공공데이터포털의 단기예보 서비스는 별도 경로이므로 API허브 문서와 사양을 혼용하지 않는다. [API허브 공식 문서](https://apihub.kma.go.kr/apiList.do?seqApi=10), [공공데이터포털 서비스](https://www.data.go.kr/data/15084084/openapi.do)

**화면 제안:**

- 위치는 농장에 등록한 주소·좌표를 기준으로 한다. 사용자가 외출했다고 휴대전화 위치의 날씨로 바뀌지 않게 한다.
- 메인에 최저·최고기온, 비 관련 정보, 필요하면 바람을 표시한다. 어떤 정보가 실제 작업 판단에 쓰이는지는 인터뷰로 확인한다.
- ‘외부 예보’와 ‘A동 내부 측정값’을 다른 이름·출처·시각으로 표시한다.
- 5칸을 고정해 그리기 전에 선택한 API의 실제 응답이 해당 날짜를 제공하는지 확인한다. 제공되지 않은 날짜는 ‘미제공’으로 처리하거나 별도 중기예보 연계를 검토한다.
- 늦게 받은 예보·조회 실패·정상 조회 후 위험 없음은 서로 다른 상태다.

이번 조사에서는 인증키를 발급받거나 실제 예보 API를 호출하지 않았다. 정확한 응답 필드·허용량·캐시는 선정한 API의 현재 문서와 실응답으로 확정해야 한다.

### 4.3 재해정보는 ‘지역·기간·출처’와 연계 가능성부터 확인한다

농사로는 농장 맞춤 기상재해 정보를 날씨·위험·대응 정보의 관계로 소개한다. [농사로 공식 서비스 설명, 2025년 영상](https://www.nongsaro.go.kr/portal/ps/psb/psby/vodPlay.ps?menuId=PS65512&mvpNo=3614)

다만 **이번 열람 시 agmet.kr에는 2026년 12월 말까지 홈페이지를 중단하고 개인별 알림톡·문자는 정상 운영한다는 안내가 노출됐다.** 홈페이지 중단과 API 중단은 같은 뜻이 아니며, 외부 API의 이용 가능 여부·권한·화훼 지원 범위는 이번 조사에서 확인하지 못했다. [현재 홈페이지 안내](https://agmet.kr/index.html)

**화면 제안:**

- ‘10월 재해정보’에는 이미 지난 정보가 섞일 수 있다. 행동이 필요한 항목은 ‘우리 지역 주의정보’처럼 현재 유효성을 드러낸다.
- 정보에 지역, 대상 품목이 있으면 품목, 발표일, 유효기간, 제공기관, 원문을 함께 둔다.
- 기상특보, 병해충 예찰정보, 지원사업 공고를 동일한 위험 경보로 합치지 않는다.
- 공공 경보를 확인하지 못한 상태를 ‘안전’이나 ‘재해 없음’으로 표시하지 않는다.
- 일반 지역 기상특보만으로 우리 온실의 피해나 병해충 발생을 확정하지 않는다.

연계가 검증되기 전에는 출처가 분명한 공지·원문 연결 방식까지를 우선 후보로 삼는다.

### 4.4 ‘수입 - 지출’은 집계 기준을 이름에 드러낸다

농사로의 농산물소득조사는 총수입과 경영비를 구분하며, 비용 항목에는 종묘·비료·농약·수도광열·감가상각 등이 포함된다. 따라서 장부에 입력한 입금·출금의 차액을 곧바로 농업소득이나 순이익으로 부르기는 어렵다. [농사로 공식 소득조사 설명](https://www.nongsaro.go.kr/portal/ps/psz/psza/contentMain.ps?menuId=PS65442)

**초기 화면 제안:** 수기 장부를 기반으로 한다면 ‘10월 입금’, ‘10월 출금’, ‘10월 입출금 차액’으로 표시한다. 판매 기준이라면 판매와 비용의 집계 기준부터 별도로 정한다.

- 실제 입금과 아직 받지 않은 출하대금, 예상 매출을 구분한다.
- 출하일과 정산·입금일이 다를 수 있으므로 월 집계에 사용하는 날짜를 정한다.
- 시장 경매가격을 농가의 실제 입금액으로 넣지 않는다.
- 선택한 A동의 값인지 전체 농장의 값인지 제목에 표시한다.
- 미입력 금액을 자동으로 0원으로 보지 않는다. 장부 조회가 실패한 경우 차액 계산도 보류한다.

### 4.5 시세는 내 기록과 비교할 때 거래단위부터 맞춘다

양재 화훼공판장 안내는 절화 시세를 속 단위, 난·관엽 등 분화는 분 단위로 설명하고, 경매가격에 거래 제비용이 포함되지 않는다고 밝힌다. aT는 경락가격 정보 API도 안내한다. [공식 경매시세 이용 안내](https://flower.at.or.kr/yfmc/front/stat/aucPrice.do?menuId=23), [공식 데이터 개방 안내](https://flower.at.or.kr/api/apiOpenInfo.do)

**제안:** 장미의 원/속과 호접란의 원/분을 같은 가격으로 비교하지 않는다. 품목·품종·등급·규격·거래일·시장·단위를 함께 확인하고 실제 정산과 분리한다. 스케치에 없는 큰 시세 영역을 임의로 추가하지 말고, 출하 판단에 실제 필요한 경우 보조 정보로 둔다.

| 현재 재배 | 정식일·수확일·출하예정일 (`B14:B16`) | 현재 단계, 확인일, 다음 수확/출하, 단계 이력, 진행률 기준 |
| 오늘 할 일 | 작업일·전정·분갈이·방제·비료·관수 등 (`A48:C58`) | 예정일·대상·상태·완료시각·반복 일정·실적 기록 연결 |
| 외부 날씨 | 내부·외부 환경 항목 (`A19:B35`) | 미래 예보의 발표시각·대상시각·지점·출처. 외부 센서값이 예보를 대신하지 않음 |
| 재해·주의정보 | 별도 피드 정의 없음 | 정보 ID·종류·지역·품목·발표/유효 시각·원문·취소/종료 상태 |
| 월 장부 | 출하 수량·등급별 단가 (`A59:B69`) | 입출금일·금액·유형·비용분류·연결 출하/작업·집계 범위 |
| 실제 생육 | 측정일·생육주차·초장·초폭·엽수 등 (`A36:C47`) | 대표 식물체 ID·대상 구역·관찰 기준. 이 값만으로 성숙도 %를 계산하지 않음 |

장부와 미래 작업 계획은 기존 엑셀을 화면에 배치하는 것만으로 구현되지 않는다. 추가 업무 정의가 필요한 범위다.

## 6. 다음 프로토타입의 정보구조 제안

스케치의 배치를 크게 바꾸기보다 표시 기준과 상호작용을 보강한다.

```text
농산물품질 / 농장 선택                        사용자 / 로그아웃
재배관리    장부    영농일기    마이영농

오늘 할 일 · 전체 농장       선택 온실 A / B / C / 온실 더 보기
대상·시간·작업·상태          베드·품종·현재 단계·최근 확인
작업 완료 → 실적 기록       다음 수확·출하 예정 / 최근 기록

우리 지역 주의정보           농장 외부 날씨 · 예보 발표시각
지역·출처·유효기간           오늘~제공 범위 · 최저/최고·강수 등

이번 달 입금               이번 달 출금              입출금 차액
전체 농장·같은 집계기간     장부 원문으로 이동        집계 기준 표시
```

### 선택 범위는 두 종류로 분리

- **전체 농장 기준:** 오늘의 전체 작업, 외부 날씨, 지역 주의정보, 월 장부 요약. 각 제목에 범위 표시.
- **선택한 재배 기준:** 온실·베드·품종·재배 건의 단계·예정일·최근 작업·생육 관찰. 선택한 대상이 제목에 계속 보이게 함.

온실을 바꿔도 전체 농장의 장부는 그대로라면 그 이유가 화면에서 이해되어야 한다. 동수가 많을 때는 A~R 탭을 모두 펼치기보다 선택 목록이나 ‘온실 더 보기’를 함께 검토한다.

### KRDS를 적용할 지점

기존 농산물품질의 헤더·색상·공통 클래스는 유지하고, KRDS의 탐색·탭·선택·입력·상태·모달 규칙을 사용한다. KRDS 컴포넌트는 표현과 상호작용의 기준이며, 재배 단계나 장부 지표의 의미는 도메인에서 별도로 정의한다. [KRDS 공식 컴포넌트 안내](https://www.krds.go.kr/html/site/component/component_summary.html)

## 7. 화면 제작 전에 검증할 질문

1. **작업 단위:** 같은 온실에서 베드별로 품종·정식일·작업이 달라지는가? 실제 한 건을 보여줄 수 있는가?
2. **재배 진행:** 80%를 보고 어떤 결정을 내리려 했는가? 기간·완료 작업·실제 생육 중 무엇인가?
3. **반복 수확:** 장미 재배에서 농민이 구분하는 회차와 다음 수확 계획은 어떻게 관리하는가?
4. **완료 기록:** 작업을 끝낼 때 최소한 남기는 값은 무엇인가? 예정대로 하지 못했을 때 어떻게 적는가?
5. **자동운전:** ‘자동 차광 14~16시’는 단순 예정인가, 장비에 설정된 일정인가, 실행 확인까지 되는가?
6. **기상 판단:** 아침에 최저기온·강수·풍속 중 무엇을 보고 어떤 작업을 바꾸는가?
7. **주의정보:** 농민이 지금 보는 재해·병해충 정보의 실제 출처와 확인 주기는 무엇인가?
8. **장부 기준:** 수입은 판매금액인가 입금액인가? 월 요약은 전체 농장인가 온실별인가?
9. **기록 메뉴:** 구조화된 작업기록과 자유로운 영농일기를 각각 쓰는가? 같은 작업을 두 번 입력하고 있지는 않은가?

## 8. 사용성 확인 시나리오

| 과제 | 확인할 행동·문제 |
| --- | --- |
| 아침에 오늘 가장 먼저 할 일을 찾기 | 대상 동·베드를 올바르게 찾는지, 날씨 때문에 바뀐 일정이 보이는지 |
| A동에서 B동 재배 상태로 이동 | 선택한 동·품종·재배 건을 혼동하지 않는지 |
| 예정된 관수를 완료로 기록 | 재입력 양, 실제값·예정값 혼동, 완료 취소와 기록 수정 가능 여부 |
| 장미의 다음 출하 일정을 확인 | 최초 정식일과 다음 출하 계획을 구분하는지 |
| 예보·주의정보가 갱신되지 않은 상황 확인 | 정상·위험 없음으로 오해하지 않는지 |
| 10월 장부 차액의 근거 확인 | 집계 범위·입출금일·미수금·누락 기록을 구분할 수 있는지 |

처음부터 임의의 합격시간이나 점수를 정하지 않는다. 첫 관찰에서 수행시간·잘못 선택한 대상·재입력·질문이 발생한 지점을 기록하고 개선 전후를 비교한다.

## 9. 후속 작업 우선순위

1. 현재 주 품목과 농장의 관리 단위, 진행률 의미, 장부 기준을 정한다.
2. 실제 작업 한 건과 반복 수확·출하 예시로 정보구조를 검증한다.
3. 날씨·주의정보 API의 선정·이용 조건·실응답을 확인한다. 홈페이지 공지와 API 상태를 분리해 조사한다.
4. 스케치 구조대로 낮은 충실도의 운영 메인을 구성하고 위 시나리오를 확인한다.
5. 확인된 항목만 기존 HTML·CSS·JS와 KRDS 표현으로 구체화한다.

위 우선순위는 이번 연구 결과에 따른 제안이며, 사용자 승인 없이 기존 스프린트 백로그나 구현 범위를 변경한 것은 아니다.

## 10. 조사 범위와 미확인 사항

- 공식 제품 안내, 공식 도입 사례, 농촌진흥청·기상청·aT·KRDS 공개 자료를 조사했다. 검색 결과와 본문을 구분했고, 일부 aT·Agri-note 페이지는 본문 접속 지연으로 검색 색인 및 다른 공식 본문을 함께 확인했다.
- 로그인 후 상용 제품을 직접 조작하거나 현장 인터뷰를 하지는 않았다. 경쟁 제품의 화면을 우리 사용자에게 검증된 정답으로 취급하지 않는다.
- 외부 API 키 발급·실제 호출·장비 연동·예측모델 검증은 수행하지 않았다.
- 장미의 장기 재배 특성에 관한 과거 공식 자료를 사용했지만, 그 안의 과거 품종·약제·온도 권장을 현재 운영값으로 옮기지 않았다.
- 재배 진행률의 의미는 사용자에게 질문했으며, 응답 전까지 미확정으로 둔다.
- 이번 작업의 산출물은 연구·설계 검토 문서다. 앞선 시안 코드는 수정하지 않았다.
