# 출하의 작기 생산정보·목표 연결 — v23

2026-11-03. 작기 프로젝트 등록정보를 생산정보의 원본으로 사용하고, 출하마다 실제 반출 정보를 기록한다. 기존 v22 계획과 v21 공통 예시 데이터를 유지한다.

## 화면 순서

1. 생산 작기 프로젝트 선택.
2. 농장·온실·품목·품종 자동 표시. 펼침 영역에서 회원·재배 시작일·정식일·재배면적·묘 구입처·작기 등록 수확일 확인.
3. 시작 재배수량·수량 변경·누적 출하량·현재 잔량 확인.
4. 작기의 목표 출하량·기간·등급·규격·예정 거래처와 목표까지 남은 수량·달성률 확인.
5. 이번 출하일·거래처·규격·출하량·단위·등급별 수량·메모 입력. 수확일·금액은 별도 펼침 영역에서 입력.
6. 등록/정정 후 예상 잔량·누적 출하량·남은 목표를 확인하고 저장.

출하 상세도 같은 생산정보·목표를 표시한다. 실제 수확일·금액·차감 재배수량은 실제 출하 기록에서 바로 확인한다. 목록은 작기명·품목·품종·농장·온실을 함께 보여주고 같은 작기로 이동한다.

## 원본과 입력의 구분

| 정보 | 기준 |
| --- | --- |
| 회원·농장·온실·작기 생산정보 | 기존 `cycleId → houseId → farmId`와 회원 공통 원본 참조. 출하에 생산정보를 복제하지 않음 |
| 시작 재배수량 | 기존 `cycle.initial` 사용. 실제 생산량으로 이름·의미를 바꾸지 않음 |
| 수량 변경·누적 출하·잔량 | 기존 수량 변경 원장 및 취소를 제외한 출하의 `stockQuantity` 규칙 사용 |
| 목표 수량·기간·등급·규격·거래처 | 기존 작기 목표를 조회. 실제 출하 수량·등급·날짜로 자동 저장하지 않음 |
| 신규 거래처·규격 | 작기 목표에서 초안으로 불러오며 수정 가능 |
| 실제 출하 | 기존 출하 원본에 실제 값 저장. 작기 목표는 바꾸지 않음 |
| 수확일 | 작기에 등록된 수확일과 이번 출하 수확일을 구분. 목표 날짜를 실제 수확일로 복사하지 않음 |

작기를 변경하면 자동으로 불러왔고 수정하지 않은 거래처·규격만 새 목표값으로 갱신한다. 직접 입력하거나 의도적으로 비운 값은 유지한다. ‘목표 거래처·규격 적용’을 명시적으로 누르면 선택 작기의 두 값을 다시 적용한다. 출하 정정은 기존 거래처·규격·등급·금액·수확일을 유지하며 목표값으로 덮어쓰지 않는다.

## 계산과 저장 보존

- 예상 수량 계산은 초안 조회이며 저장소에 쓰지 않는다.
- 정정에서는 같은 작기의 기존 출하 차감분을 되돌린 가용 수량에서 새 차감량을 계산한다. 다른 작기로 정정하면 그 작기의 잔량을 기준으로 한다.
- 출하 단위가 재배 단위와 다르면 사용자가 입력한 차감 재배수량으로 예상·목표 실적을 계산한다. kg을 화분 수로 자동 환산하지 않는다.
- 등급 체계·등급별 합계 검증·소수 출하량·수량 원장·정정/취소 규칙은 기존 저장소를 그대로 사용한다. 기존 비표준 등급도 원기록에서 유지한다.
- 새로운 저장 키·마이그레이션·수량 변경 이력·계획 데이터는 만들지 않는다. 같은 작기의 생산정보·출하 목표 변경은 다음 조회에서 반영된다.
- 실적 저장 후 작기 계획의 달성률·목표까지 남은 수량도 같은 출하 원장을 참조한다.
