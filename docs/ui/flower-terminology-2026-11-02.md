# 화훼 영농관리 용어 기준과 UI 반영

> 후속 최종 데이터는 [Google Sheets 261102 기준과 UI 매핑](../data/final-data-ui-mapping-2026-11-02.md)을 따른다. 기존 첨부 XLSX보다 우선한다. 화서수는 원자료 항목명으로 입력하고, 화색은 자료의 0~5 평가점수로 입력한다. 기존 봉오리 수·실제 색상과 자동 변환하지 않는다. 아래 내용은 이전 첨부자료 대조 기록이다.

작성일: 2026-11-02. 첨부 네 자료의 실제 용어를 대조하고, 서비스에서 사용할 의미·원자료와 다른 해석·추가 확인 항목을 구분했다. 원본 PDF·XLSX는 수정하지 않았다.

상위 메뉴(홈·재배관리·기준정보 관리·기간별 비교·통계·마이페이지)는 유지했다. 자료의 ‘영농일지’는 기존 합의한 ‘재배일지’의 기능 참고 이름으로 취급하고 메뉴를 다시 바꾸지 않았다.

## 3. 그대로 확정하지 않은 항목

1. **수확일=재배완료일(S4 B15):** 수확·실제 출하·작기 종료는 다른 사건으로 정의한다. 실제 정식일도 작기 관리 시작일과 자동으로 같게 만들지 않는다.
2. **화서수=꽃봉오리 수(S4 B43):** 원문 병기 의미가 불명확하다. 꽃대 수·봉오리 수·개화 수를 구분하고, 화서수를 봉오리 수의 별칭으로 자동 매핑하지 않는다. 호접란 1차 논문도 화서장과 화서당 소화수를 별도 특성으로 제시한다.
3. **대표 식물체 10% 이상(S4 A36):** 작성자 초안의 권장 문구다. 공식 호접란 조사 기준으로 검증된 비율이 아니므로 입력 강제·자동 표본 수 산정에 사용하지 않는다.
4. **평균엽장·평균엽폭(S4 B41:B42):** 단일 잎의 엽장·엽폭과 합치지 않는다. 평균 대상·개수·방법을 따로 정한다.
5. **화색 정상 5~불량 0(S4 B46):** 꽃 색과 품질 등급의 개념을 구분한다. 평가 기준이 없는 보편 점수로 사용하지 않는다.
6. **재배면적은 AI 값(S4 D17):** 산출 기능과 근거가 없으므로 자동 계산값으로 표시하지 않는다. 현재 UI는 수기로 등록하는 온실면적이다.
7. **광도·일사량·DLI(S4 B23:B24·B27):** 센서 종류·순간/누적·단위를 확인한다. 조도와 PPFD, 복사에너지와 일적산광량을 단위 이름만 바꾸어 변환하지 않는다.
8. **HD의 산식·단위(S3 2·5쪽):** 보고서의 단위/해석과 실제 센서·계산 정의를 별도 확인해야 한다. VPD·배지 수분·관수량과 합치지 않고 기본 정상 범위도 넣지 않는다.
9. **수확·등급별 물량/단가(S4 B59:B69):** 실제 품목·상품·단위를 확인하고 적용한다. 특상/특/중/하를 호접란의 공통 확정 등급으로 강제하지 않는다.
10. **출하시기 추천/경락가격(S1 13쪽, S4 B70:B79):** 참고 시장가격·예측과 농장의 실제 출하 실적은 별개다. 기존 출하 비교는 실적·목표 비교로 유지한다.

## 5. 저장 데이터·UI 호환

- 표시·별칭 기준은 `producerTerminology.js`가 소유한다. `growth`의 별칭만 정규화하며 알 수 없는 항목은 원래 이름을 유지한다.
- 과거 생육 측정값을 원본에서 일괄 변경하지 않는다. UI에서 같은 뜻의 이름만 정리하며 개체·단위·방법이 다른 값은 합치지 않는다. 일지 수정 시 기존 측정명은 `sourceMetric`에 보존한다.
- 평균엽장/엽장, 평균엽폭/엽폭, 화서수/봉오리 수는 서로 다른 항목이다. 생육 그래프 조회조건의 이전 별칭도 현재 항목으로 연결한다.
- 이전 출하 `grade` 필드는 당시 화면상 규격이었다. 새 필드 `specification`이 없는 기록은 이를 규격으로만 표시하고 등급은 미등록으로 둔다. 정정 저장 시 규격·등급을 분리해 보존한다.
- 정식일은 선택 필드이며 기존 재배 시작일을 복제하지 않는다. 실제 정식일을 입력했을 때만 표시한다.
- 기존 URL·ID·v3 저장 키·이전 시안 원본을 유지한다. 용어 변경으로 출하량·잔량 계산식을 바꾸지 않는다.
- 품질담당자와 맞춘 공통 CSS·그리드·헤더·사이드·입력/표 밀도도 유지한다.
