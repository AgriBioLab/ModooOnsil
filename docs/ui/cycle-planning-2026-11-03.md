# 작기 목표·단계·데일리 계획 연결 — v22

2026-11-03. 기존 공통 데이터 UI 프로토타입에 계획→실적 업무를 추가한다. 별도 체험 모드는 없다.

## 화면과 작업 흐름

작기 상세 상단에서 현재 재배수량, 목표 출하량, 실제 출하량, 목표까지 남은 수량, 예정기간, 목표 등급·규격·예정 거래처와 달성률을 확인한다. 실제 출하량은 기존 `stockQuantity` 규칙에 따른 재배 차감 수량으로 계산한다. 취소 출하는 제외한다. 계획량은 재고에서 차감하지 않는다.

오늘 할 일은 당일·완료·지연 건수를 먼저 표시하고 미리보기를 펼칠 수 있다. 기본정보 / 계획 / 재배일지 / 출하 이력 / 수량 변경의 다섯 탭으로 구분한다. 계획 탭에서는 단계 추가·수정, 단계에 작업 추가, 일일 작업 추가·수정, 날짜·하루/7일/전체·상태 조회, 지연 작업, 데일리 가이드를 제공한다.

작업의 ‘작업 기록’으로 진입하면 같은 작기와 계획이 선택된 일지를 작성한다. 실제 날짜·내용과 진행 중/완료를 저장하고, 일지 상세에서 원래 계획으로 돌아간다. 일지에서 계획을 직접 선택할 수도 있다. 작기를 바꾸면 계획 선택을 초기화하고 새 작기의 작업만 제공한다.

홈 체크사항은 선택 온실에 연결된 진행 작기의 공통 작업을 읽는다. 온실 상세는 선택 작기의 당일·완료·지연 건수와 계획 진입을 제공한다. 일지·센서 통합조회도 같은 작기의 해당 일자 계획을 연결한다. 전체 메뉴의 작기관리 → 목표·작업계획에 진입점을 추가한다.

## 공통 데이터

| 데이터 | 주요 항목 | 관계 |
| --- | --- | --- |
| 기존 `cycles` 목표 | `targetQty`, `targetStart`, `targetEnd`, 추가 `targetGrade`, `targetSpecification`, `targetRecipient` | 기존 목표 수량·기간을 재사용. 별도 목표 복제 없음 |
| `planStages` | `id`, `cycleId`, `name`, `start`, `end`, `goal`, `criteria`, `history` | 작기 아래 단계별 일정·목표·완료 기준 |
| `planTasks` | `id`, `cycleId`, `stageId`, `date`, `time`, `title`, `type`, `zone`, `assignee`, `priority`, `quantity`, `unit`, `status`, `criteria`, `reason`, `history` | 같은 작기의 단계 또는 개별 작업 |
| 기존 `records` 확장 | `planTaskId`, `planOutcome` | 한 계획에 여러 일지 연결 가능. 기존 독립 일지도 유지 |
| 자동 실행 연결 | 작업의 `automationEventId` | 같은 작기·날짜의 기존 실행 원본 조회 |
| 가이드 기준 | 작기의 `planGuide`, `guideHistory` | 조사 주기·온도/습도 확인 범위와 변경 이력 |
| 변경 이력 | 작기의 `targetHistory`, 단계·작업의 `history` | 목표·일정 변경 전 값과 사유 보존 |

기본 작업 상태는 예정·진행 중·연기·생략이다. **완료는 연결된 실제 일지의 완료 결과 또는 장치 실행 완료 응답으로 계산**하며 직접 완료 상태만 저장할 수 없다. 완료 근거 일지를 수정·연결 해제·삭제하면 남은 실적으로 상태를 다시 계산한다. 실패 실행이나 센서 관측 수신만으로 완료하지 않는다. 지연은 기준일 이전이며 완료·생략이 아닌 작업에서 계산한다. 출하 달성률과 작업 완료율은 분리한다.

날짜 변경 및 연기·생략에는 사유가 필요하다. 계획·일지 간 작기 불일치와 자동 실행 계획의 직접 수정을 차단한다. 종료 작기는 계획을 보관하고 신규 계획·가이드 변경을 제한한다. 종료 전에 잡아 둔 미래 일정도 삭제하지 않는다.

## 데일리 가이드

- 최근 실제 생육조사일과 작기별 조사 주기로 다음 확인 여부를 계산한다. 꽃대·봉오리 / 개화·출하 / 입고·활착 등 현재 단계에 따라 관찰 항목을 바꾼다.
- 당일 관측 누락, 품질상 집계 제외, 등록된 온도·습도 범위 이탈을 구분한다. 범위 비교는 유효하고 단위가 일치하는 값만 사용한다.
- 자동 실행 실패, 출하기간 접근, 이전 일지의 후속 확인 메모를 함께 제안한다.
- 제안의 근거와 완료 기준을 표시하고 ‘계획에 추가’를 눌러 작업으로 등록한다. 같은 작기·날짜·가이드는 중복 등록하지 않는다.
- 조사 주기는 1~90일, 환경 확인 범위는 작기에서 수정한다. 온도·습도 범위를 비우면 해당 상한·하한 비교를 적용하지 않는다. 기준 변경은 이미 등록한 작업을 바꾸지 않는다.

초기 조사 주기 7일, 온도 18~28°C, 습도 55~80%는 UI 동작 확인을 위한 하드코딩 값이며 재배 기술 권장값이 아니다. 실제 제어 명령이나 외부 센서 통신은 없다.

## 초기화와 보존

첫 적용 시 현재 등록된 작기에 단계·당일·주간·출하 준비 작업을 한 번 보충한다. `planningDataVersion=1`로 재접속·새로고침 때 중복 생성하지 않는다. 보충 전 저장 원본은 `agribiolab-producer-management-v3-before-planning22`에 보관한다. 이후 새 작기는 사용자가 단계·작업을 등록하거나 데일리 가이드를 계획에 추가한다.

기존 기록·관측·수량·출하·등급을 재작성하지 않는다. 목표기간 변경 후 단계 일정이 다르면 검토 링크를 표시하며 기존 일정을 자동 이동하지 않는다. 브라우저 저장소 v3와 기존 URL을 유지한다. 공유용 단일 HTML도 같은 모듈을 포함한다.
