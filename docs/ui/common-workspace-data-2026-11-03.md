# 회원·농장·온실·작기·기록 공통 연결 — v15

실행 화면: `src/main/webapp/view/producerMain.html?v=common-data-v15-20261103&view=cycles`

## 공통 데이터 범위

현재 UI의 단일 회원 작업공간에서 `profile`과 `farms`를 연결하고, `farms.id → houses.farmId → cycles.houseId → records/adjustments/shipments.cycleId`를 조회한다. `ProducerManagementStore.context(state, ref)`가 작기·일지·수량 변경·출하 ID에서 회원·농장·온실·작기를 일관되게 해석한다. 이름은 표시값이며 연결 키로 사용하지 않는다. 없는 ID나 서로 다른 온실·작기 조합은 다른 기록으로 대체하지 않는다.

회원 작업공간의 농장을 내 정보에 표시하고, 농장 상세에서는 같은 원본의 온실을 조회한다. 온실 상세의 농장명과 작기의 회원·농장·온실 정보에서 관련 상세로 이동한다. 재배일지·수량변경·출하의 연결 정보도 같은 원본으로 구성한다. 회원명·농장명·온실명·작기명·품종을 바꾸면 조회 화면에 반영되며 각 기록의 날짜·수량·사유는 그대로 유지한다.

복수 회원 인증·소속 권한을 새로 만든 것은 아니다. 현재 작업공간에는 회원 프로필 하나가 있으며 등록 농장은 그 작업공간의 농장이다. 실제 회원별 접근 권한은 인증·서버 연계 범위로 남겨 둔다. 기존 기록에 임의의 소유자나 회원 ID를 삽입하지 않는다.

## 검색과 명칭

- 온실명·작기 상태·작기명·품종을 같은 검색 박스에서 모두 펼친다. 기존 공통 레이아웃이 세 번째 필드부터 상세 조건으로 접던 규칙을 작기 목록에는 적용하지 않는다.
- 1024px 이상에서는 네 조건을 한 줄로, 중간 폭은 두 열, 모바일은 한 열로 표시한다. 조회·초기화는 같은 박스 안에 둔다.
- 온실은 ID로 선택하며 선택지에 소속 농장명도 표시해 같은 이름의 온실을 구분한다. 작기명과 품종은 부분 검색하고 네 조건을 함께 적용한다.
- 위치의 현재 기준은 **농장 → 온실**이다. 주소는 농장 정보, 구역·베드는 온실 시설정보다. 작기별 베드·이동 위치를 새로 만들거나 자동 배정하지 않는다.
- 작기명은 사용자가 입력하는 프로젝트명으로 유지한다. 출하 시기·품종·차수 등의 안내 예시만 제공한다. 영문+번호 규칙·자동 명명·이름에 따른 연결은 강제하지 않는다. 표시명을 변경해도 내부 작기 ID로 이력 연결을 유지한다.
- 목록에서 품목·품종·생육단계는 별도 열이다. 진행·종료 상태도 별도 열로 유지한다.

## 번호와 페이지 이동

작기·농장·온실·일지·출하 및 작기의 수량 변경 이력에 번호와 페이지 이동을 제공한다. 번호는 검색 결과의 연속 행 번호이며 DB ID와 구분한다. 페이지당 10·20·50개, 번호별 이동·처음·이전·다음·마지막을 제공한다. 한 페이지인 목록도 현재 페이지와 비활성 이동 버튼을 표시한다. 결과가 없으면 빈 결과를 안내한다.

페이지 이동은 검색 조건을 유지한다. 새 검색·초기화·표시 개수 변경은 첫 페이지로 이동한다. 표시 개수는 화면 높이에 따라 바뀌지 않는다. 실제 저장 데이터에 페이지 번호나 인덱스를 추가하지 않는다. 비교 원자료·용어 안내 등 보조 표의 기존 미리보기 크기는 유지한다.

## 로그아웃

내 정보 오른쪽과 모바일 메뉴에 로그아웃을 추가했다. 현재 생산자 인증 서버가 없으므로 **공개 시작 화면으로 이동하는 UI 동작**이다. 실제 서버 세션 종료라고 표시하거나 계정 인증을 가장하지 않는다. 회원·농장·온실·작기·일지·수량·출하 저장소는 지우지 않는다. 입력 중이면 기존 미저장 이탈 안내에서 계속 작성 또는 저장하지 않고 이동을 선택한다. 단일 HTML의 시작 화면 경로도 수정했다.
