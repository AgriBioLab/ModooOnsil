- 작성일: 2026년 10월 22일
- 상태: 회고 초안 — 준비 자료와 Jira 기록을 바탕으로 작성. 참석자 피드백·실제 합의 결과는 추가 확인 필요
- 범위: 킥오프 준비와 실행계획의 회고. 2차 스프린트 개발 성과에 대한 평가는 종료 후 별도 작성

## 1. 회고 요약

이번 킥오프 준비에서는 1차에서 보완할 점을 Spring 전환, 신규 기능, 협업 규칙, 테스트와 일정으로 연결했다. 품질담당자의 통계·전년도 비교와 생산자의 피해신청 흐름을 구분하고, 리팩토링을 먼저 진행하는 실행계획을 마련한 점을 유지할 수 있다.

다음으로 보완할 부분은 준비한 계획을 팀의 실제 결정으로 연결하는 기록이다. 현재 확인한 자료에는 담당자·페어·가용 시간, 기술 구성·DB 선택, API·집계 기준 등에 미정 사항이 남아 있다. 각 항목의 선택 이유와 담당·기한을 남겨야 구현 착수와 완료 판단의 기준으로 사용할 수 있다.

위 평가는 문서 검토에 따른 초안이다. 강사님이나 팀원의 발언, 발표 만족도, 회의 시간 준수 여부는 확인된 기록이 없어 평가하지 않았다.

## 3. 유지할 점 — Keep

### 업무 목적과 사용자 흐름에서 기능을 설명한 점

통계·비교분석의 목적을 품질담당자의 의사결정과 연결하고, 생산자는 가입 → 피해신청 → 본인 조회로 정리했다. 기능별 설계와 시연에서도 누가 어떤 업무를 완료하는지 설명하는 방식을 유지한다.

### 1차 회고를 구체적인 개선 항목으로 연결한 점

업무 용어, UI·ERD 누락, 조건별 테스트, 조회 지연, 회의 목적·결정 근거를 설계·구현·검증 항목으로 연결했다. 다음 보고에서도 ‘기존 문제 → 선택 이유 → 조치 → 검증 결과’의 흐름으로 개선 여부를 설명한다.

### 전환과 검증을 일정에 포함한 점

대표 기능 전환을 먼저 확인하고 신규 기능을 연결하며, 마지막 주에는 통합·회귀와 결함 수정 시간을 배치했다. 구현 일정이 밀릴 때 검증 시간을 유지할 수 있도록 기능 우선순위와 축소 범위를 함께 정한다.

## 4. 보완할 점 — Problem

아래 항목은 준비 자료에 남은 미결 사항과 실행 위험에 대한 검토 의견이다. 회의에서 실제로 발생한 문제나 참석자의 평가로 확정한 내용은 아니다.

| 보완점 | 실행에 미치는 영향 | 필요한 보완 |
|---|---|---|
| 제안·합의·수행 완료의 구분 | 자료에 있는 항목을 이미 결정하거나 구현한 것으로 오해할 수 있음 | 회의 후 결정·보류·추가 조사로 구분하고 결정자·일자·이유 기록 |
| 기술 전환과 기능 추가가 함께 포함됨 | Spring·데이터 접근·DB 전환에 필요한 공수가 신규 기능 일정에 영향을 줄 수 있음 | 대표 경로 검증과 실제 공수 확인 후 필수·후속 범위 조정 |
| 담당자·페어·가용 시간 미정 | 병렬 작업과 일정의 실현 가능성을 판단하기 어려움 | 책임자·페어·검토자·가용 시간을 배정하고 선행 관계 재확인 |
| 지표·API·권한의 세부 기준 미정 | 화면·DB·테스트에서 서로 다른 기준으로 구현할 수 있음 | 집계 날짜·비교 기간·대상 상태, API명·필드, 본인 조회·서류 권한 명세 |
| 회의 결과와 후속 업무의 연결 기록 부족 | 어떤 의견이 채택되었고 다음 행동이 무엇인지 추적하기 어려움 | 피드백마다 조치·관련 Jira·담당·기한·완료 증거 연결 |

## 7. 공유용 요약 초안

2차 스프린트 킥오프를 준비하면서 1차에서 보완할 점을 기술 전환, 기능 설계, 협업과 검증 계획으로 구체화했다. 품질담당자와 생산자의 업무 흐름을 구분하고 리팩토링과 통합 검증을 일정에 포함한 점은 유지할 부분이다. 다음 단계에서는 실제 회의 피드백과 합의 결과를 기록하고, 담당자·페어·기술 선택·기능별 완료 기준을 확정해야 한다. 대표 기능 전환 결과와 가용 시간을 바탕으로 범위를 조정하며 후속 업무를 추적한다.
