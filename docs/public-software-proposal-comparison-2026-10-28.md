# 농업 생산자 서비스 — 공공 소프트웨어 발주·운영 사례 비교

확인일: 2026-10-28 / 대상: 공공기관이 생산자에게 재배공정 소프트웨어를 제공하는 현재 기획

> 최신 서비스 방향: [1차·2차 스프린트 개요](sprint1-sprint2-service-overview-2026-10-28.md). 핵심은 2차의 생산자 정보·재배기록을 후속 지원·피해보상 업무에서 활용하는 연결이다. 이 비교는 기능·운영 참고자료이며, 서비스 목적을 온실 관제나 기관 선정 문제로 대체하지 않는다.

## 1. 비교 결론

**공공기관이 생산자용 농장관리 소프트웨어를 제공·운영한다는 설정에는 실제 근거가 있다.** 공공기관은 사업 기획·운영과 생산자 지원을 맡고 민간 사업자가 구축·기술지원을 맡는 형태로 설명할 수 있다.

현재 기획은 환경·공정·이력·설정 관리라는 방향이 실무와 맞는다. 다만 ‘노동력 감소와 기후변화’라는 배경을 구체적인 농작업과 소프트웨어 동작으로 연결하고, 제공기관·생산자·기술수행자의 역할을 구분해야 한다. AI와 보상환경은 각각 근거와 검증 범위를 정한 확장 제안으로 제시한다.

아래는 원문 요구사항 및 공개 운영사례와의 비교다. 발주문서의 기능을 실제 구축·운영 완료 기능으로 간주하지 않았고, 과거 운영사례를 2026년 현재의 운영 확인으로 확대하지 않았다.

## 3. 원문에서 확인한 비교 근거

### A. 부안군 — 제공기관과 구축자의 역할이 명확한 과업

과업은 기상·영농 데이터 활용을 추진 배경으로 두고 농가용 반응형 웹, 환경·생육 현황, 영농일지, 이상 알림, AI 지식서비스 등을 요구한다. 농업기술센터 과학영농팀이 기획·검수·운영·관리를 맡고 사업자가 구축한다. 기능·연계·AI 응답 등에 대한 시험도 포함한다. **요구사항이라는 점이 중요하며 운영 실적으로 인용하지 않는다.**

원문 위치: 인쇄 p.1~4(파일 p.3~6), p.9(파일 p.11), 요구사항 목록 p.12(파일 p.14), AI 시험표 p.46(파일 p.48). [과업지시서 원문](https://www.g2b.go.kr/pn/pnp/pnpe/UntyAtchFile/downloadFile.do?bidPbancNo=R26BK01706314&bidPbancOrd=000&fileSeq=3&fileType=&prcmBsneSeCd=03), [공고 원문](https://www.g2b.go.kr/pn/pnp/pnpe/UntyAtchFile/downloadFile.do?bidPbancNo=R26BK01706314&bidPbancOrd=000&fileSeq=2&fileType=&prcmBsneSeCd=03)

이 문서에서 직접 원격제어 명령을 수행하는 요구는 확인하지 못했다. 따라서 우리 원격제어 범위의 근거는 B·C를 별도로 참고한다. AI 관련 문항별 시험 기준은 해당 발주의 조건이며 우리 모델의 성능 기준으로 그대로 복사하지 않는다.

### B. 화성시 — 현장 문제와 원격관리의 연결

2018년 보고서는 당시 포도 농가의 물 관리와 여러 농장 운영, 장비 사후관리 문제를 배경으로 제시한다. PC·스마트폰에서 정보 확인·장비 제어, 이상 통보, 지도상담을 설명하며 센터와 민간업체의 역할을 구분한다. **생산자 지원기관이 서비스 제공자가 될 수 있음을 보여주는 과거 사례**다. 보고서가 재인용한 인력 절감률은 우리 화훼 서비스의 예상 효과로 사용하지 않는다.

원문 위치: 인쇄 p.13~14(파일 p.19~20), p.19(파일 p.25). [공개 보고서 원문](https://clik.nanet.go.kr/clikr-collection/policyinfo/69/312/2019/CLIKC16684928004351288_attach_1.pdf)

### C. 중부대학교 — 구현 경계를 구체화한 기술 제안요청서

제안요청서는 교육·연구용 서버가 센서 값과 제어명령을 수집·저장·시각화·제어하도록 요구한다. 이력·경보, 인증·암호화·백업, 표준 통신 연동도 제시한다. 우리 기획의 장비 연동 범위를 구체화하는 참고다. **대학 교육용 발주이므로 공공기관의 대농민 서비스 운영을 입증하는 자료로 사용하지 않는다.**

원문 위치: 인쇄 p.3~4(파일 p.3~4). [제안요청서 원문](https://www.g2b.go.kr/pn/pnp/pnpe/UntyAtchFile/downloadFile.do?bidPbancNo=R25BK01196274&bidPbancOrd=000&fileSeq=1&fileType=&prcmBsneSeCd=01)

### D. 청양군 — 앱 사용과 이용 교육까지 연결한 운영사례

2020년 자료는 시설원예 농가의 환경정보를 수집·분석해 청양팜 앱으로 제공하고, 농가에 앱·센서 관리 교육을 실시한 사례를 설명한다. 담당자의 컨설팅과 연결한 비대면 지원도 제시한다. 정보 제공과 이용 지원의 관계를 참고한다. 이 자료만으로 농가의 원격 설비조작이나 화훼 전용 기능까지 확인되지는 않는다. [청양군농업기술센터 작성·농진청 게시 원문](https://www.rda.go.kr/board/board.do?boardId=farmlcltinfo&dataNo=100000764622&mode=updateCnt&prgId=day_farmlcltinfoEntry)

### E. ASTIS — 재배제어와 구별해야 하는 공공 온라인 지원

2024년 발표는 생산자의 비대면 신청·상담과 과학영농서비스 이용 이력, 기관 담당자의 데이터 활용을 설명한다. 공공기관이 생산자에게 온라인 서비스를 제공하는 근거로 활용할 수 있다. 해당 발표를 온실 원격제어 기능의 근거로 사용하지 않는다. [농진청 ASTIS 운영 발표](https://www.rda.go.kr/board/board.do?boardId=farmprmninfo&dataNo=100000796868&mode=updateCnt&prgId=day_farmprmninfoEntry)

## 4. 현재 기획과 비교한 판단

프로젝트 기준: [27일 재배공정 기획안](floriculture-greenhouse-service-brief-2026-10-27.md), [28일 제공자·배경 제안](public-provider-selection-proposal-2026-10-28.md). 현재 목표는 농업 관련 공공기관의 생산자 지원이며, 지역 한정 여부는 실제 대상사업을 정할 때 구체화한다.

| 비교 항목 | 실무 자료에서 참고할 점 | 현재 기획 판단 | 보완안 |
|---|---|---|---|
| 공공 제공기관 | A·B는 공공 기획·운영과 민간 구축을 구분 | 제공자 설정에 근거 있음 | 공공기관=사업·서비스 운영, 우리 팀=소프트웨어 제안·개발, 생산자=이용자로 명시 |
| 기관 선정 순서 | B·D는 생산자 현장 지원의 맥락 | 사용자 방향과 일치 | 생산자 지원기관을 먼저 선정. 보상 기능의 존재를 선정 조건으로 두지 않음 |
| 노동력 감소 | B는 구체적인 농장 운영 부담에서 출발 | 문제 표현이 아직 넓음 | 순회 확인·반복 조작·기록 조회 중 줄일 업무를 지정 |
| 기후변화 대응 | A는 관측·영농정보와 대응 지원을 연결 | 온도 현황만으로는 대응 설명이 부족 | 확인→알림→조작/조치→결과 기록으로 대응 흐름 정의 |
| 생산자 공정 | A의 농가 정보, B·C의 운영 기록을 참고 | 구역·단계·설정·이력 방향은 타당 | 화훼 한 품종·한 작형에 맞춘 대표 시나리오 작성 |
| 원격제어 | B·C를 근거로 구체 검토 가능 | 실장비·명령·실제 상태 범위가 관건 | 제어 대상과 연동 조건, 응답·미응답, 동작 확인을 명세 |
| AI | A처럼 수행할 일과 시험을 정의할 필요 | 현재는 장기 고도화 방향 | 2차 공정관리와 후속 AI 후보를 분리하고 AI가 필요한 판단을 먼저 정함 |
| 교육·사후지원 | A·D의 운영 관점 참고 | 기능 목록에 비해 제공체계 설명 부족 | 생산자 사용 안내, 장애 문의·장치 점검 책임, 지원 이력 구분 |
| 보상환경 | 이번 비교자료에서 해당 통합 기능은 확인하지 못함 | 기존 공공 기능이 아닌 우리 제안으로 적절 | 같은 기관의 후속 확장임을 표시. 2차에 추가 개발하지 않음 |

위 보완안은 원문을 그대로 옮긴 요구가 아니라 프로젝트 범위에 맞춘 분석·제안이다. 비교 사례가 모든 농가나 모든 공공기관에 동일하게 적용된다는 뜻은 아니다.

## 5. 소프트웨어 관점에서 구체화할 최소 업무

현재 여섯 기능을 모두 크게 넓히기보다 다음 흐름을 하나의 검증 가능한 업무로 정의한다.

1. 생산자가 자신의 온실·구역과 재배 단계를 선택한다.
2. 현재 환경·적용 설정·측정 시각·설비 상태를 확인한다.
3. 설정한 기준 이탈 또는 데이터 미수신을 구분해 확인한다.
4. 연동 가능한 설비를 조작하고 요청·응답·실제 상태를 확인한다.
5. 환경 변화와 설정·조작·조치 이력을 다시 조회한다.

실제 장비가 없으면 시뮬레이션으로 구분한다. 이 경우 소프트웨어 흐름은 검증할 수 있지만 현장 노동 절감이나 재해 예방 효과가 검증된 것은 아니다.

| 목적 | 제안하는 확인 방법 | 아직 단정할 수 없는 효과 |
|---|---|---|
| 순회·확인 부담 완화 | 특정 구역의 상태 확인에 필요한 단계·시간 비교 | 실제 노동시간·인건비 절감률 |
| 이상 상황 대응 지원 | 기준 이탈을 인지하고 관련 기록을 찾는 시나리오 | 기후재해 피해 감소율 |
| 원격 조작의 확인 가능성 | 응답·미응답·장치 상태 불일치를 구별하는지 확인 | 현장 설비의 신뢰성·연간 가동률 |
| 기록 활용 | 구역·기간별 작업과 환경·조작 이력을 찾는지 확인 | 데이터만으로 피해 원인을 확정하는 판단 |

## 6. AI·보상 확장의 위치

AI는 ‘데이터가 쌓이면 가능하다’는 설명에서 더 구체화해야 한다. 후속 후보를 정할 때 **입력자료, 도움을 줄 판단, 결과를 사용하는 사람, 비교 기준, 검증 방법**을 함께 정의한다. 아직 학습·성능 검증이 없다면 AI 분석 기능이 구현된 것으로 소개하지 않는다.

보상환경 서비스는 생산자 지원기관에 제안하는 후속 서비스다. 품질담당자의 보상 모니터링·통계·보상 품질 평가·예측·전략·예산 계획 역할을 유지하며 복구지원이나 지급 집행을 맡기는 것으로 설명하지 않는다. 공정 기록을 보상 판단에 사용하려면 자료의 의미와 실제 사용 범위를 별도로 정해야 한다.

1차에 보상 지급결과 조회를 먼저 구현했다는 개발 순서와, 생산자 지원기관에서 서비스를 확장한다는 기획 방향은 구분한다. 2차는 생산자 재배공정에 집중한다.

## 7. 비교 결과를 반영한 배경 문안 — 3줄

농촌의 일손이 줄면서 생산자가 온실을 오가며 환경을 확인하고 설비를 조작하는 부담을 줄일 방법이 필요합니다.  
기후변화에 대응하려면 재배환경의 변화를 확인하고 필요한 환기·난방 등의 조치를 제때 수행할 수 있어야 합니다.  
이에 농업 관련 공공기관이 생산자에게 온실 현황·원격조작·관리 이력을 연결한 소프트웨어를 제공하고, 이용 교육과 기술지원을 함께 운영하는 방안을 제안합니다.

이 문안은 실무 구조를 참고해 작성한 우리 제안이다. 특정 사업의 문구를 인용하거나 노동 절감·피해 예방 성과를 보장한 표현이 아니다. 제공 대상이 특정 지역의 사업 참여 농가라면 ‘관내 대상 농가’로 구체화한다.

## 8. 자료의 공개·이용 조건과 한계

- ASTIS 게시물: 공공누리 제1유형 표시를 확인했다. 출처를 표시해 참고한다.
- 청양군 게시물: 공공누리 제4유형 표시를 확인했다. 이번에는 사실관계의 비교와 원문 링크를 제공하며 사진·본문을 수정해 재배포하지 않는다.
- 부안군·중부대 발주문서 및 2018 보고서: 원문은 공개 접근 가능했으나 각 문서의 공공누리 적용 표시는 확인하지 못했다. 공공누리 제1유형 자료라고 소개하지 않는다.
- 민간 입찰정보 사이트는 문서 위치를 찾는 데만 활용했다. 최종 분석은 나라장터 원문과 기관 자료에 근거한다. 기존 공고의 취소·재공고 혼동을 피하기 위해 부안군은 위에 명시한 R26BK01706314 첨부를 기준으로 했다.
- 발주·설계의 존재, 당시 운영 기록, 현재 운영 상태, 실측 성과는 각각 다른 증거다. 이번에는 계약·검수 완료, 현장 실측, 담당자 인터뷰까지 확인하지 않았다.
