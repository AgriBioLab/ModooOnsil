# 화훼 온실 재배공정 통합 관리·제어 서비스 기획안

작성일: 2026-10-27

> 최신 제공자 선정안: [생산자 지원기관과 보상환경 서비스 확장 제안](public-provider-selection-proposal-2026-10-28.md). 실제 생산자 지원기관을 먼저 선정하고, 같은 기관에 향후 보상환경 서비스를 추가 제안한다. 2차는 생산자의 재배공정 관리에 집중한다. 아래 사기업·기술센터 후보에 대한 과거 설명보다 이 기준을 우선한다.

> 최신 제공기관 기준: [1차 기반 2차 단일 공공 제공기관·배경](sprint2-single-public-provider-background-2026-10-28.md). 1차 피해보상 모니터링과 2차 생산자 재배공정은 같은 공공기관의 서비스로 설정한다. 아래 사기업 제공자 설정은 이전 초안이다. 재배공정 기능은 2차 범위 검토의 참고로 활용하며, 품질담당자·피해보상 추가 작업은 후속으로 둔다.

> 2026-10-28 피드백 후속: 사기업 선정 배경과 공공부문 역할, 1차 스프린트와의 관계를 [공공부문·생산공정 조사](feedback-public-sector-research-2026-10-28.md)에서 재검토했다. 아래 사기업 제공자 설정은 27일 초안이며, 제공 주체·주 액터가 최종 확정된 상태는 아니다.

문서 성격: 공식 기업 자료와 공공기관의 현장 사례를 참고한 서비스 기획 초안. 아래 사례의 사실과 이번 서비스에 제안하는 설계를 구분한다. 페르소나와 니즈는 현장 인터뷰 전 가설이며, 실제 기업 담당자나 농민의 인터뷰 결과를 의미하지 않는다.

## 1. 주제

**화훼 생산자를 위한 PC·모바일 기반 온실 재배공정 통합 모니터링 및 중앙·원격제어 서비스**

서비스 제공자는 온실의 센서와 제어 설비를 연결하고 시스템 구축·운영을 지원하는 사기업이다. 서비스 대상자는 온실 환경에서 화훼류를 재배하는 농민이다. 생산자는 재배 조건을 결정하고 자신의 온실 공정을 운영하는 주 액터다.

조건에 따른 자동제어도 서비스 구성에 포함할 수 있다. 첫 스프린트의 구현 범위는 별도로 정하며, 이 문서에서는 온도 관리 공정을 첫 검증 대상으로 제안한다.

## 2. 개요

### 2.1 서비스 정의

> 본 서비스는 온실에서 화훼를 재배하는 생산자가 PC와 모바일로 재배환경과 설비 상태를 확인하고, 여러 온실·구역의 설비를 중앙·원격 제어하도록 지원한다. 생산자가 설정한 재배 조건에 따른 자동 운전과 환경·설정·조작 이력 관리를 제공하며, 서비스 제공 기업은 현장 설비 연동, 시스템 구축, 운영 및 유지보수를 담당한다.

PC에서는 여러 온실의 상태 비교와 설정 관리를, 모바일에서는 현장·외부에서의 상태 확인과 신속한 조작을 주요 사용 상황으로 설계한다. PC와 모바일 모두 권한 내에서 조회·제어할 수 있으며, 기능을 기기에 따라 배타적으로 나누지 않는다.

### 2.2 용어와 서비스 경계

| 용어 | 이번 기획에서의 의미 |
|---|---|
| 재배공정 | 화훼를 기르기 위한 단계별 환경 관리와 작업. 실제 단계와 완료 기준은 품목·재배 방식에 따라 정함 |
| 관리 단위 | 농장 → 온실 → 재배구역. 품목·품종·재배 배치를 해당 구역과 연결 |
| 중앙제어 | 권한이 있는 여러 온실·구역을 한 화면에서 파악하고 개별 또는 선택 그룹별로 설정·조작 |
| 원격제어 | 생산자가 현장 밖에서도 PC·모바일을 통해 설비에 조작 명령을 내림 |
| 자동제어 | 생산자가 적용한 운전 조건에 따라 시스템·현장 제어기가 설비를 작동시킴 |
| 레시피 | 대상 구역·재배 단계·시간대에 적용할 환경 목표와 설비 운전 조건을 묶은 설정 |
| 생육 확인 | 식물의 실제 상태를 관찰·기록하는 일. 온도 등 환경 측정과 구분 |

첫 검증에서 온도만 사용한다면 현재 온도, 목표 범위, 설비 상태와 온도 관리 이력을 다룬다. 개화 상태 판정이나 수확 시기 예측은 별도의 생육 정보와 검증이 필요한 후속 범위로 둔다.

## 3. 페르소나와 니즈

### 3.1 주 페르소나 — 서비스를 이용하는 화훼 생산자

**역할:** 온실의 화훼 재배와 환경 관리, 설비 운전을 직접 담당하는 농장주 겸 재배 책임자.

**대표 상황:** 여러 온실·구역을 오가며 꽃과 환경을 확인한다. 농장 사무실에서는 PC를, 현장 작업 중이나 외출 중에는 모바일을 사용한다. 일부 관리 작업은 가족 또는 함께 일하는 사람과 나눌 수 있다. 이는 R2·R4의 사용 상황을 바탕으로 구성한 가설이다.

| 항목 | 페르소나 정의 |
|---|---|
| 목표 | 품목과 재배 단계에 맞는 환경을 관리하고, 필요한 작업을 제때 수행 |
| 예상 불편 | 온실마다 상태를 확인하러 이동해야 함. 외부에서 설비의 실제 작동 여부를 확인하기 어려움. 적용 조건과 과거 조작을 다시 찾기 어려움 |
| 정보 니즈 | 어느 온실에 확인이 필요한지, 현재 값과 적용 설정이 무엇인지, 설비가 실제로 작동하는지 |
| 제어 니즈 | 개별·그룹별 조작, 현장 밖에서의 제어, 자동·수동 운전 상태 확인과 전환 |
| 기록 니즈 | 온도 변화와 설정·조작·이상 이력을 같은 시간 흐름에서 확인 |
| 사용성 니즈 | 구역명과 현재 상태가 분명한 화면, 적은 단계의 조작, 요청 결과와 연결 끊김의 명확한 표시 |

가상 대표 발화: “온실을 돌아다니거나 농장에 다시 가지 않아도 상태를 확인하고, 필요한 설비를 조작한 뒤 실제로 작동했는지 알고 싶다.”

### 3.2 제공자 측 페르소나 — 기업의 서비스 운영 담당자

**역할:** 농가에 시스템을 도입하고 센서·제어 설비 연결, 설정 지원, 장애 점검·유지보수를 담당한다. 기업의 기획·영업 전체를 한 사용자에게 묶기보다, 실제 운영 화면을 사용할 역할로 정의한다.

**대표 상황:** 여러 고객 농장의 장치 연결과 서비스 상태를 확인하고, 문의가 들어오면 해당 농장의 설정·명령·응답 이력으로 문제를 파악한다. R1·R6을 참고한 가설이다.

| 항목 | 페르소나 정의 |
|---|---|
| 목표 | 농장별 설비를 연결하고 지속적으로 운영할 수 있는 서비스를 제공 |
| 예상 불편 | 농장마다 설비·통신 방식과 운전 조건이 다름. 장애가 센서·통신·제어기 중 어디에서 발생했는지 구분하기 어려움 |
| 도입 니즈 | 농장·온실·구역·장치 관계 등록, 지원 가능한 장비 확인, 연결·동작 검증 |
| 운영 니즈 | 고객 농장별 연결 상태, 마지막 수신 시각, 오류와 조치 이력 확인 |
| 지원 니즈 | 생산자의 문의와 관련된 설정·조작 이력을 찾아 원인을 설명하고 대응 |
| 권한 니즈 | 농장별 접근 범위를 구분하고, 지원을 위해 수행한 변경을 추적 |

가상 대표 발화: “고객 농장의 어떤 장치에서 문제가 생겼는지 파악하고, 설정과 실행 이력을 근거로 지원하고 싶다.”

생산자가 자신의 재배 조건을 결정하고 운전한다. 기업 담당자는 계약·부여 권한의 범위에서 기술 운영을 지원한다. 기업의 중앙 운영 화면에서 모든 농장의 재배 조건을 임의 변경하는 모델로 가정하지 않는다.

## 4. 요구사항

아래는 R1~R6과 사용자 요청을 바탕으로 도출한 제안 요구사항이다. 각 사례가 아래 세부 동작을 모두 제공한다는 뜻은 아니다.

| ID | 요구사항 | 확인 가능한 완료 기준 | 도출 근거 |
|---|---|---|---|
| REQ-01 | 농장·온실·구역과 재배 정보를 관리한다. | 구역에 품목·품종·재배 배치·현재 단계를 연결해 조회할 수 있다. 단계는 생산자가 등록·변경하며 온도만으로 자동 판정하지 않는다. | R3·R4, 재배공정 관리 목적에서 확장 |
| REQ-02 | 환경 측정값과 설비 상태를 모니터링한다. | 온도 값·단위·측정 시각, 설정값, 설비 상태를 함께 표시한다. 갱신되지 않은 데이터는 현재 값과 구분한다. | R1·R2·R5 |
| REQ-03 | 여러 온실·구역을 중앙에서 관리한다. | 개별·그룹별로 대상을 선택하고 설정을 적용한다. 그룹 적용 결과는 대상별 성공·실패·미확인 상태로 확인한다. | R2·R3·R4에서 세부 동작 설계 |
| REQ-04 | PC·모바일에서 원격제어한다. | 권한이 있는 설비를 조작하고 요청·응답·실제 상태 확인 결과를 조회한다. 상태 피드백이 없으면 실행 완료로 표시하지 않는다. | R2·R4·R6에서 세부 동작 설계 |
| REQ-05 | 재배 조건을 레시피로 저장·적용한다. | 대상·단계·시간대·온도 조건을 저장하고 현재 적용 중인 설정을 확인한다. 설정 저장과 현장 적용 결과를 구분한다. | R1·R3·R5, 첨부 메모 |
| REQ-06 | 자동·수동 운전을 구분한다. | 현재 모드를 표시하고 전환을 기록한다. 수동 조작 후 자동 운전 복귀 방식과 시점을 명확히 정한다. | 사용자 요청과 공정 제어 설계 |
| REQ-07 | 이상을 알리고 조치 상태를 관리한다. | 설정한 온도 기준 이탈, 데이터 미수신, 제어 실패를 구분해 표시하고 확인·조치 이력을 남긴다. | R6에서 세부 동작 설계 |
| REQ-08 | 환경·설정·조작 이력을 연결한다. | 온실·구역·기간별로 측정값, 설정 변경, 조작자·시각·명령·결과와 이상 이력을 조회한다. | R5, 첨부 메모 |
| REQ-09 | 레시피와 운영 결과를 비교한다. | 설정값 차이와 적용 기간별 온도 변화·설비 가동 기록을 비교한다. 조건 차이만으로 재배 효과의 인과관계를 단정하지 않는다. | R2·R5, 첨부 메모에서 확장 |
| REQ-10 | 제공자가 설비 연결과 장애를 관리한다. | 권한이 부여된 농장의 장치 연결·마지막 수신·오류와 조치 내역을 확인한다. | R1·R6 |
| REQ-11 | 접근과 조작을 추적한다. | 생산자는 자신의 농장을 사용하고 제공자 담당자는 배정된 지원 범위에 접근한다. 설정 변경과 조작에 사용자·대상·시각을 기록한다. | 서비스 제공자·이용자 분리에 따른 설계 |

설비 제어 기능은 연동 가능한 현장 제어기·통신과 작동 확인 수단을 전제로 한다. 실장비 연동 전에는 시뮬레이션임을 표시하고 명령 전송, 실패·미응답, 상태 피드백을 각각 시연한다. 재배 기준 온도는 품목·품종·단계와 현장 운영 기준에 맞춰 정하며 이 문서에서는 공통 수치를 지정하지 않는다.

## 5. 핵심기능

첨부 메모의 여섯 기능을 생산자 업무에 맞춰 아래와 같이 구성한다.

| 기능 | 생산자가 수행하는 일 | 온도 관리 공정의 화면·동작 예시 | 연결 요구사항 |
|---|---|---|---|
| 1. 재배공정 현황 | 어느 온실·구역이 어떤 조건으로 운영되는지 확인 | 전체 온실 카드, 현재 온도·설정값·운전 모드·설비 상태·이상 표시 | REQ-01·02·07 |
| 2. 재배공정 이력 | 과거 조건과 작업·조치 내용을 조회 | 온도 그래프와 설정 변경·설비 조작·이상 기록을 같은 시간축에서 조회 | REQ-08 |
| 3. 재배환경 레시피 설정 | 재배 단계·시간대별 관리 조건을 저장·적용 | 구역별 목표 온도·설비 운전 조건 입력, 적용 상태·변경 이력 확인 | REQ-05·06 |
| 4. 레시피 비교 | 두 설정의 차이를 확인 | 목표 온도·시간대·운전 조건의 차이와 적용 기간 표시 | REQ-09 |
| 5. 설비 중앙·원격제어 | 개별·그룹별 설비를 PC·모바일로 조작 | 대상 선택, 난방 시작·정지, 모드 전환, 대상별 실행 결과 확인 | REQ-03·04·06 |
| 6. 재배공정 운영 통계 | 환경 유지와 설비 운영 결과를 확인 | 설정 범위 내·외 체류 시간, 가동 시간, 이상 발생 횟수 | REQ-09 |

생산자 화면의 공통 기능으로 알림과 접근 권한을 적용한다. 제공자에게는 별도의 농장·장치 연결·장애 관리 기능을 제공한다. 설비 가동 시간과 실제 에너지 사용량은 구분하며, 에너지 사용량·요금 통계는 별도 계측·산정 근거를 확보한 경우 추가한다.

### 5.1 첫 스프린트의 권장 검증 범위

**검증 목표:** “생산자가 두 개 이상의 온실·구역의 온도와 설비 상태를 PC에서 확인하고, 모바일로 한 구역을 원격 조작한 뒤 실제 결과와 이력을 확인한다.”

우선 연결할 기능은 온실·구역 등록, 온도·설비 현황, 개별·그룹 중앙제어, 모바일 원격제어, 조작 이력과 실패·미응답 표시다. 온도 조건 설정과 자동 운전까지 구현한다면 자동·수동 모드 및 조건 충족에 따른 작동 결과를 함께 검증한다. 레시피 비교와 운영 통계는 이후 스프린트로 분리할 수 있다.

검증 시나리오:

1. 생산자가 PC에서 두 온실의 온도·측정 시각·난방 상태를 확인한다.
2. 적용할 온실들을 선택해 설정을 변경하고, 온실별 적용 결과를 확인한다.
3. 모바일에서 한 온실의 난방을 조작한다.
4. 명령 요청과 설비 상태 피드백을 확인하고, PC에서도 같은 상태·이력을 조회한다.
5. 한 온실의 응답이 없거나 데이터가 갱신되지 않는 상황을 만들어 다른 온실과 구분되는지 확인한다.
6. 제공자 담당자가 해당 장치의 연결·오류·조작 이력으로 지원 상황을 파악한다.

### 5.2 페르소나 검증에 필요한 현장 질문

- 생산자: 실제로 자주 조작하는 설비와 판단 기준은 무엇인가? PC·모바일을 각각 언제 사용하는가? 현재의 원격 조작에서 무엇을 확인하기 어려운가?
- 생산자: 여러 온실에 같은 설정을 적용하는 경우와 구역별로 다르게 운전하는 경우는 언제인가? 가족·작업자와 업무를 어떻게 나누는가?
- 제공자: 연결 가능한 센서·제어기는 무엇이며, 실제 작동 상태를 어떤 방식으로 확인하는가? 장애 문의 시 어떤 이력이 필요한가?
- 공통: 재배 조건 변경의 담당자, 제공자의 지원 범위, 수동 운전 및 자동 복귀 규칙은 어떻게 정할 것인가?

이 질문으로 가설을 검증한 후 상세 화면·스프린트 백로그와 구현 범위를 확정한다.
